* DRY原則を守るためのdir構成
** 発想
いくつものStackで何度も同じことを説明する必要が出てきます．
ですが，それをそれぞれのStackで書き直すとDRY原則が破綻します．
documentのDRY原則を一人のPC内で実現しようというのが
ここでの設定です．

実装方法の議論は下につけたpre-search項を参照．

** Manual by Codex
共有したいディレクトリへのsymlinkをStack内に置き，
​=.hc_config.yaml=​ に相対位置を登録します．
#+begin_src yaml
:shared_dirs:
  - c6_fukumori/hc_vs_others
#+end_src
メイン同期でsymlinkを扱わず，public側の共有先を保護するため，
​=.rsync_filter=​ にも登録します．
#+begin_src text
- /c6_fukumori/hc_vs_others
#+end_src
Rakefileは通常同期から登録パスを除外し，
続けてリンク先の内容だけをpublicへ同期します．
#+begin_src ruby
shared_paths = shared_directories(config[:shared_dirs])
exclude_options = shared_paths.map do |path|
  "--exclude=/#{path}"
end
rsync_directory(
  source_dir: PROJECT_ROOT,
  target_dir: $public_repository_dir,
  extra_options: exclude_options
)
shared_paths.each do |path|
  rsync_directory(
    source_dir: File.join(PROJECT_ROOT, path),
    target_dir: File.join($public_repository_dir, path)
  )
end
#+end_src
​=rake rsync_public dry_run=​ で変更予定を確認し，
​=rake rsync_public=​ で実同期します．

public側にはsymlinkではなく実ファイルが作られ，
未登録または ​=:shared_dirs: []=​ なら通常同期だけを実行します．

はい，自動化できます．そして重要な点として，​=.rsync_filter=​
に除外設定を足すだけではコピーされません．

現在はRakefileに ​=--no-links=​ があるため，動作は次のようになります．

#+begin_src text
.rsync_filterで除外
    → メイン同期の対象外になる
    → public側では保護される
    → しかしリンク先の内容はコピーされない
#+end_src

したがって，選択したsymlinkだけをpublicへ展開するには，別途rsyncを実行する処理が必要です．それを毎回手動で実行することもできますが，​=rake rsync_public=​
の一部として自動化するのがよいと思います．

おすすめは，​=.hc_config.yaml=​ に共有ディレクトリだけを宣言する方式です．

#+begin_src yaml
:shared_directories:
  - c4_hc_vs_others
#+end_src

Rakefile側では，この設定を読んで次の2段階を自動実行します．

1. 通常のStack全体をrsyncする．共有ディレクトリは除外して，public側を削除から保護する．
2. 共有ディレクトリのsymlink先を解決し，public内の同名ディレクトリへ別途rsyncする．

つまり，利用時の操作は従来どおりです．

#+begin_src sh
rake rsync_public dry_run
rake rsync_public
#+end_src

各Stackで必要なのは，次の2点だけになります．

#+begin_src text
c4_hc_vs_others という相対symlinkを置く
.hc_config.yaml の shared_directories に名前を書く
#+end_src

​=.rsync_filter=​
への除外追加もRakefile側で動的に行えるため，手で両方へ同じディレクトリ名を書く必要はありません．設定を二重管理しない点でも，この方がDRYです．

なお，単純に ​=--copy-links=​
を使えばRakefileの変更は小さくできますが，対象外のsymlinkまで追跡してしまいます．「設定された共有ディレクトリだけを2回目のrsyncで展開する」方式が安全です．
